# Optimization review, October 10, 2026

Scope: the Swift/Python OpenRagnar checkout, focusing on delegated navigation, visual actions, memory recall, request telemetry and dashboard refresh. The graph index and targeted source reads were checked together. This is a focused performance review, not an exhaustive security audit or a completed comparison against Neo directly.

## Implemented

1. **Remove unnecessary readiness waits.** Navigation previously waited up to eight seconds for `a[href]` even when the answer was already visible on a linkless page. Readiness now resolves when the expected text or a usable link appears. A DOM observer handles delayed content; the deadline remains eight seconds and the observer/timer are released afterward. A separate observation still verifies completion.
2. **Combine revalidation and navigation.** The current URL, visible selected href and download exclusion are checked in the same browser run that follows the link. The final observation remains separate. This removes one gateway-to-Neo call per followed link, reducing a one-link task from five calls to four. It narrows the gap between the check and navigation but does not make the browser action atomic.
3. **Defer optional work.** The first observation and local verified-route lookup precede provider-key access and advisory recall. Already-satisfied tasks, tasks with no eligible links, and verified routes avoid those unnecessary steps. A new decision still receives bounded memory hints. Cancellation is rechecked before spending inference and before dispatch.
4. **Keep accounting honest.** Attempted browser calls are counted even when dispatch fails, and reported navigation duration includes synchronous outcome storage. No additional paid model pass or automatic retry was introduced.

## Live evidence

The comparison used baseline commit `7d65730` (0.4.6) and the 0.4.7 candidate on the same Mac and Neo instance. The task followed the public TypeSafe models page to the API reference and verified `floats that sum to 1`. Selection was deterministic, so neither version called Jev or another model. Each three-run block used temporary memory and closed only its owned tabs. Remote recall was deliberately unavailable and background uploads were disabled. Order was baseline, candidate, candidate, baseline, with three runs per block. Final timing was repeated without overlapping the other validation scripts.

| Public documentation task | Baseline | Candidate |
| --- | ---: | ---: |
| Verified completions | 6/6 | 6/6 |
| Median elapsed time, measured around the complete call | 0.7626 s | 0.7142 s |
| Browser calls per task | 5 | 4 |
| Selector calls on first / second / learned third run | 1 / 1 / 0 | 1 / 1 / 0 |
| Provider loads on the learned third run | 1 | 0 |
| Advisory recalls on the learned third run | 1 | 0 |

This sample is about 6.4% lower median elapsed time and 20% fewer gateway-to-Neo calls. Six runs per version on one task are too few to establish a general speed advantage. Network/browser caches were not reset. First-run means empty experience memory, not a cold browser/model. The deterministic selector cannot measure paid-model latency, Claude usage or money saved.

A separate controlled fixture replaced the body of an owned example.com tab with the requested text and no anchors before the readiness wait. Both versions verified the same text with two browser calls: baseline took 8.2077 s, candidate 0.1249 s. This demonstrates removal of the eight-second wait in that specific case, not a broad 10× claim. A live removed-link injection caused the candidate to return `stale_link` and leave the tab at the original URL. Additional live checks passed for immediate answer text, delayed answer text and visible-link readiness.

Local evidence files are ignored artifacts: `dist/navigation-comparison-0.4.7.json`, `dist/navigation-guards-0.4.7.json`, and the source/release test logs. The standard public-page learning check remains reproducible with `python3 neo-personal/live_learning.py` and makes no paid decision-model call. Automated readiness tests execute the actual page-side function with controlled DOM events and timers.

## Next priorities toward the product target

| Priority | Finding | Next acceptance gate |
| --- | --- | --- |
| Highest | Ordinary forwarded browser tools still rely on the main agent for planning; delegated navigation covers public links and visual actions cover one target. | A bounded multi-step task executor with explicit completion criteria, current-state checks and escalation. Measure how many main-agent turns it actually replaces at equal correctness. |
| High | Gateway counters retain provider tokens, while provider-reported monetary cost is not yet aggregated into durable per-task cost. Main-agent billing remains outside the gateway. | Store reported provider cost separately from estimates and unknowns; import client totals for matched task comparisons. Include failures and memory costs in cost per successful task. |
| High | Route and visual reuse cover narrow matching tasks/scenes. More stored outcomes alone do not establish broader learning. | Test reusable procedures on changed content/layout while preserving live verification and failure invalidation. Compare first-run and learned-repeat completion rates. |
| Lower, profile first | Local vision validates provider metadata before inference; dashboard refresh starts a Python snapshot process every six seconds. | Profile their actual contribution before changing them. Preserve the check preventing local screenshots from being sent through an Ollama remote model. Suppress unnecessary hidden-window polling only if measured useful. |

The next major benchmark must include the real main agent using Neo directly, OpenRagnar local, and OpenRagnar cloud on the same representative task set. This pass improves known overhead inside OpenRagnar; it does not yet establish 10× end-to-end speed, general cloud/local superiority, or Claude subscription savings.
