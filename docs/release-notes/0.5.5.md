# BrowserHelm 0.5.5

Supported multi-step read-only tasks now receive a clear executor preference during MCP initialization, removing the competing generic run instruction. Routing guidance is shorter while retaining completion checks, partial-progress recovery, DOM-first vision selection, human approvals and protection against repeating possibly completed writes.

- Initialization guidance is 16.6% smaller in the controlled delegation/vision-enabled comparison: 2,974 to 2,479 UTF-8 bytes. The full tool catalog and available tools are unchanged.
- Project and benchmark guidance now target 10× fewer client-reported main-agent tokens per independently verified task. Speed, accuracy and total cost remain separate measures.
- Added regression coverage for routing priority and retained verification/recovery/vision boundaries.

This release does not establish 10× task-token savings, faster task completion, lower subscription usage or lower total cost. No provider choices, credentials, experience memory or saved settings are changed. See the benchmark procedure in docs/benchmarks.md for matched comparisons.

## Validation

245 engine tests, 32 script/privacy tests and five benchmark-oracle tests passed. The engine suite passed using the packaged Python 3.12 runtime. Native release build, read-only DMG verification, strict installed-app signature verification and fresh installed MCP negotiation passed for version 0.5.5. Settings bytes and SQLite row counts were preserved during installation.

Requires an Apple Silicon Mac running macOS 14+ and BrowserOS Neo. This preview is ad-hoc signed and **not notarized**; it is not a Developer ID-signed production release. Reconnect existing Claude/Codex MCP clients after updating.
