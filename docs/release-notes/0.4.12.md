# OpenRagnar 0.4.12

Addresses overhead found in the six-case Opus High pilot:

- Task start/finish guidance is opt-in under **Settings → Browser execution → Ask agent to mark tasks**, defaulting to off for new and existing settings. Explicit tools and manual task controls remain available. Request/session diagnostics continue to work; prompts are not guessed from idle gaps.
- Executor steps advertise separate action-specific schemas. Navigation requires literal destination `text`; only visual `locate` accepts `instruction`. Invalid arguments return corrective guidance before dispatch.
- `neo_help(topic="openragnar_execute")` provides examples before catalog discovery. Help also recognizes the other OpenRagnar tools.
- Inspection defaults to headings and links. Computed styles require `includeStyles: true` or targeted `extract` fields with `read: "style"`.
- Text extraction identifies truncation, original character count and excerpt offset. Optional `contains` returns up to 1,200 characters around a literal phrase; a missing phrase returns `missing_text` and null, rather than an unrelated beginning-of-page excerpt.

Freshness, verification, budgets, same-origin restrictions, cancellation, output recovery and learning validation remain enforced. No provider change or extra inference pass is required.

These fixes address measured interface overhead. They do not establish a new end-to-end speed/cost result or the 10× target. The original 18-task baseline is retained. Further paid host comparisons await usage review and authorization.

Local build uses ad-hoc signing; Developer ID signing/notarization remains pending.
